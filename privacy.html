隐私政策Privacy policy

更新日期：2026 年 10 月 21 日 · 适用于个人自动化应用及本介绍网站Updated: 21 October 2026 · Covers the personal automation app and this informational website

本政策依据现有应用代码撰写。联系邮箱尚待补充，因此当前版本尚未准备好用于公开发布或 OAuth 提交。This policy reflects the existing application code. A contact email is still required, so this version is not yet ready for publication or OAuth submission.

01

应用与范围Application and scope

本工具由开发者自行运行，仅处理开发者自己的通知与 Google 主日历。静态网站本身不登录 Google、不请求 OAuth 授权，也不接收通知或日历数据。The developer runs this tool for personal notifications and the developer’s own primary Google Calendar. This static website does not sign in to Google, request OAuth consent, or receive notification or calendar data.

02

Google API 权限Google API permission

应用请求 https://www.googleapis.com/auth/calendar.events，允许查看和编辑可访问日历中的事件，包括创建和删除。当前代码仅使用主日历的事件查询、创建及更新，没有实现事件删除，也不请求 Gmail、通讯录或 Drive 权限。授权范围比当前实际操作更广。The app requests https://www.googleapis.com/auth/calendar.events, which allows viewing and editing events on accessible calendars, including creating and deleting events. Current code only queries, creates and updates primary-calendar events; it does not implement event deletion or request Gmail, Contacts or Drive scopes. The granted scope is broader than the operations currently used.

03

日历的访问与使用Calendar access and use

应用通过 events.list 和 events.get 查询事件，以稳定标识、来源信息、标题、描述及日期检查重复。正式处理可查询截止日期前约一年至后约一年的事件，并按标识查询其他相关事件。events.insert 创建事件，events.patch 按规则更新并以 ETag 检查版本；写入后重新读取确认，写入请求不发送更新通知。The app uses events.list and events.get to check duplicates using stable identifiers, source information, titles, descriptions and dates. Live processing may query roughly one year before to one year after a deadline, plus related events by identifier. It creates events with events.insert and updates them under rules with events.patch and an ETag version check. Writes are read back for confirmation and request no update notifications.

04

写入与本地保存的数据Data written and retained locally

写入内容包括事项标题、起止日期或时间、提醒、通知证据摘录、来源文件信息及去重标识。事件描述可能包含原通知内容和来源设备文件位置；这些内容进入 Google Calendar，但不会放入本网站。服务器上的 SQLite 状态、处理报告和人工清单可能保留提取事项、事件载荷、事件 ID、链接、日期及错误信息；源文件在确认处理后按条件归档，失败时保留。归档不是删除，当前未实现统一的自动到期删除策略。Event data includes task titles, start/end dates or times, reminders, notification evidence, source-file information and deduplication identifiers. Descriptions may contain notification excerpts and source-device file locations; this information goes to Google Calendar, not this website. Server-side SQLite state, processing reports and review lists may retain extracted tasks, event payloads, IDs, links, dates and error details. Originals are conditionally archived after confirmation and retained on failure. Archiving is not deletion; there is no unified automatic expiry/deletion policy.

05

OAuth 凭据OAuth credentials

OAuth 使用 Desktop 应用授权及离线访问。客户端配置、访问 token 和刷新 token 保存在个人 Ubuntu 服务器的网站目录之外。代码要求凭据目录权限为 700、文件为 600，并检查所有者、文件类型及符号链接；token 经临时文件写入后替换。文件以 JSON 保存，未实现应用层静态加密，也不宣称安全认证。刷新 token 用于在授权有效期间获取新的访问 token。OAuth uses a Desktop application flow with offline access. Client configuration, access tokens and refresh tokens are stored outside the website directory on the personal Ubuntu server. Code requires directory permissions of 700 and file permissions of 600, checks ownership, file types and symbolic links, and replaces tokens using a temporary file. Files are stored as JSON without implemented application-level encryption at rest; no security certification is claimed. The refresh token obtains new access tokens while authorization remains valid.

06

Codex 与外部模型处理Codex and external model processing

通知正文或抓取到的通知网页文本，以及抽取规则，通过 Codex CLI 发送至其登录账户所使用的外部模型服务；现有部署记录使用 OpenAI 的 Codex / ChatGPT 登录。因此文本中包含的个人信息也可能被该服务处理，这不是完全离线分析。抽取代码禁用工具及网页搜索，不把 Google OAuth 凭据或日历查询结果作为模型输入。CLI 的 ephemeral 选项不能证明服务端零留存；服务方的保留、训练及账户控制以实际账户设置和适用条款为准，本项目无法承诺其零留存或不训练。Notification text or fetched notification-page text and extraction rules are sent through Codex CLI to the external model service associated with its signed-in account; deployment records show OpenAI Codex / ChatGPT sign-in. Any personal information in that text may therefore be processed by that service; analysis is not fully offline. Extraction disables tools and web search and does not pass Google OAuth credentials or queried calendar results as model input. The CLI ephemeral option does not establish zero server-side retention. Provider retention, training and account controls depend on actual account settings and applicable terms; this project cannot promise zero retention or no training.

07

第三方与共享目的Third parties and purposes

Google 接收授权请求、日历查询及事件写入数据以提供 Calendar 功能。Codex 所用外部模型服务接收上述通知文本以抽取事项。Syncthing 在配置的个人设备间同步文件、归档及人工清单；如使用中继，会涉及其连接基础设施。通知链接处理还会访问相应网站以获取正文。现有代码没有出售数据或向广告商提供数据的流程；但不能将上述处理表述为“绝不与第三方共享”。Google receives authorization requests, calendar queries and event writes to provide Calendar functionality. The external model service used by Codex receives the notification text described above for task extraction. Syncthing syncs files, archives and review lists between configured personal devices; relays, if used, involve its connection infrastructure. Notification-link processing also contacts the corresponding websites to retrieve text. Current code has no data-sale or advertising-sharing workflow, but these operations cannot be described as never sharing data with third parties.

08

撤销授权与删除Revocation and deletion

可前往 Google 账户的第三方连接，选择本应用并移除访问权限。撤销阻止后续授权访问，但不自动删除已创建的事件、本地文件、报告或同步副本。开发者可停止任务、删除本地 OAuth token、按需删除 Google Calendar 中的事件及本地状态、报告、归档和各设备副本；清理前需注意去重状态丢失可能导致重新处理。第三方已接收数据的删除以其政策及账户控制为准。Visit Google Account third-party connections, select this app and remove access. Revocation prevents further authorized access but does not automatically delete previously created events, local files, reports or synced copies. The developer can stop the task, remove local OAuth tokens, and delete Calendar events, local state, reports, archives and device copies as needed. Removing deduplication state may cause reprocessing. Deletion of data already received by providers is governed by their policies and account controls.

09

网站访问与联系Website visits and contact

本站不包含分析脚本、广告、第三方字体或表单，不使用 Cookie 或浏览器存储。语言切换仅更新当前页面的 URL 参数。部署后的托管商仍可能按自身政策处理 IP 地址及请求日志。隐私问题或删除请求请联系开发者：邮箱待补充。数据流变更后应相应更新本政策。This site includes no analytics scripts, advertising, third-party fonts or forms and uses no cookies or browser storage. Language selection only updates the current page’s URL parameter. Once deployed, the hosting provider may process IP addresses and request logs under its own policy. Contact the developer for privacy questions or deletion requests: email pending. This policy should be updated when data flows change.
